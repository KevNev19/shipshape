How it works

From bare repo to protected, in one conversation

Run $shipshape-init in Codex, or /shipshape-init in Claude Code, in any repository from an empty folder to a ten-year-old codebase. Nothing in your project changes until you have seen the whole plan and said go.

  1. 1

    Scan

    It reads your project to learn its languages, how it installs packages and how its tests run. It only looks.

  2. 2

    A few questions

    Five at most, about outcomes: who works on it, how changes should land, how you check it works, what must never leak, and whether it's public. What the scan already knows is only confirmed.

  3. 3

    Preview

    Every file it will add, one line each, with what it's for. Files you already have are listed apart and left alone unless you say yes to that exact file.

  4. 4

    Set up

    It writes exactly what you saw and switches on the commit guard. A GitHub rule that protects main is added only if you say yes.

How it feels

Plain questions. A plan you can read.

Shipshape asks about how you work, in everyday words. It confirms what it found instead of guessing, and every term of art gets a short explanation the first time it comes up.

Everything it writes is standard, boring, reliable tooling. Remove the plugin tomorrow and your setup keeps working.

After your next push the checks start running on GitHub, a guard watches every commit on your computer, and a docs/sdlc/ folder explains the whole setup.

On watch

What's watching your back

Security is the centre of the kit, not an add-on. Everything here that fits your project comes switched on for a solo, straight-to-main setup, except the branch rule, which waits for your yes. Switching off a security guard or the health check means hearing the consequence in one plain sentence, and saying yes anyway.

Commands

Eight commands, two hosts

Each one is a short conversation. In Codex, type $shipshape-init; in Claude Code, /shipshape-init. Doctor and review only look and report. Init, customize, access, release and intent show you exactly what they will do and wait for your yes.

  • $shipshape-init

    The front door

    Scans your project, asks a few questions, shows every file it will add, then sets it up.

    Previews first

  • $shipshape-doctor

    Health check

    Checks your setup and its guards. Problems come first, then one thing to do next.

    Read-only

  • $shipshape-review

    Plain-language review

    Explains a change in plain words and ends on a clear verdict. It never edits or merges.

    Read-only

  • $shipshape-release

    Guided releases

    Checks your tests passed on GitHub, suggests a version, and publishes only on your yes.

    Asks first

  • $shipshape-access

    Who can do what

    “Give Sam access”, in plain words. You see the exact command before it runs.

    Asks first

  • $shipshape-customize

    Off the defaults

    Change a setting by asking. You see what will change, and only those files are rewritten.

    Previews first

  • $shipshape-intent

    Say what you mean

    For bigger changes: four short answers, saved as a note before work starts.

    Optional

  • $shipshape-orchestrate

    Hand off a task

    For developers using both assistants: one hands a scoped coding task to the other, then checks the result. Needs a separate orchestrator plugin.

    For developers

In Codex, every command except doctor and orchestrate starts only when you type its name, so nothing runs by surprise.

Trust

Why you can trust it with your repo

  • Nothing is ever clobbered

    Shipshape remembers a fingerprint of every file it writes. Edit one and it becomes yours: future runs report it and ask, file by file, before touching it. A file you already had is replaced only if you say yes to that exact file.

  • Files explain themselves

    Generated files open with what they are, why you have them, and whether they're safe to edit. A glossary defines every term the tooling uses.

  • Plain words, honest verdicts

    Reviews translate failures: “the login test expected X and got Y.” A red CI never gets called “looks safe”, and a file being present is never reported as a check that ran.

  • It runs on itself

    This project was set up by shipshape: its secret guard, CodeQL, Dependabot, release workflow and weekly health check are its own output. Where a file was already hand-written, shipshape left it alone, as it will in yours.

“I left CLAUDE.md alone because it has your own edits in it. Tell me if you'd like me to replace it.”

Make it yours

One file steers everything

.sdlc/config.json holds your working style, team or solo, which guardrails are on, your test command and your reviewers. Change it with $shipshape-customize: only what's affected regenerates, and your own edits are left alone.

"profile": "solo",
"workflow_style": "trunk",
"features": {
  "codeql": true,
  "dependabot": true,
  "secret_guard": true,
  "scheduled_health": true
},
"commands": {
  "test": "python3 -m pytest tests/ -q"
}

Under the hood

Boring on purpose

  1. detect.py
  2. render.py
  3. protection.py
  4. doctor.py
  • Plain Python 3.10 or newer, using only its built-in library. Nothing to pip install.
  • Templates are plain token substitution: no template language, no conditionals.
  • Over 600 tests, plus 30 dated regression checks that keep fixed bugs from coming back.
  • Decisions recorded as architecture decision records.

Install

All aboard

In Codex

Run the first two in a terminal, then type the third in a new Codex conversation in your project.

  1. codex plugin marketplace add KevNev19/shipshape
  2. codex plugin add shipshape@shipshape
  3. $shipshape-init

In Claude Code

Type each one inside Claude Code, in your project.

  1. /plugin marketplace add KevNev19/shipshape
  2. /plugin install shipshape@shipshape
  3. /shipshape-init

Needs git and Python 3.10 or newer (check with python3 --version). On macOS, xcode-select --install provides git; get a current Python from python.org or Homebrew. On Linux, use your package manager. Releases, access changes and the GitHub branch rule also need the GitHub CLI (gh), signed in; shipshape tells you how to install it if it's missing.
