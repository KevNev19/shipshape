# End-to-end sweep — 2026-08-23

## Scope

A full live exercise of the shipshape kit against two throwaway GitHub
repositories on the owner's account, one per workflow style:

- **`KevNev19/shipshape-e2e-trunk`** — trunk-style Python project.
- **`KevNev19/shipshape-e2e-pr`** — PR-style, team profile, tiered review
  enabled.

Both were seeded as minimal real Python projects, had the kit installed
via the actual `detect → init-config → plan → apply → hook install`
pipeline, pushed to GitHub, and driven through every shipped surface with
real commits, pull requests, workflow dispatches, and a release tag. The
repositories are left in place for inspection; they are safe to delete.

## Bugs found — fix-back items for the kit

The sweep found two real defects in freshly rendered consumer output.
Both were worked around on the test repos to complete the sweep; both
should be fixed in the kit itself.

### F2 (High) — a fresh repo's first CI run fails

`templates/github/workflows/ci-python.yml.tmpl` installs the project with
`pip install -e ".[dev]"` and then runs `pytest`, but nothing in a seeded
project declares `pytest`, so the very first CI run after `init` red-fails
at the Run tests step. A kit whose promise is "green CI means safe" should
render a project that is green on arrival. Options: have `detect`/`render`
add a `dev` extra with the detected test runner when a `pyproject.toml`
exists, or fall back to `pip install pytest` in the Python CI template when
no test dependency is declared. (Node/Go/generic variants should be
checked for the same class of gap.)

### F3 (High) — the auto-merge workflow cannot merge

`templates/github/workflows/low-risk-automerge.yml.tmpl` is rendered with
`permissions: contents: read`, but enabling auto-merge is a write action;
a correctly-classified docs-only PR logged "Eligible: docs-only" and then
"Auto-merge could not be enabled." The fix is one line — the workflow
needs `contents: write` (with `pull-requests: write`) — and it does not
weaken the safety model: inspection stays API-only, no checkout, no
code execution. ADR 0008's no-execution property is unaffected.

## Not live-testable in this sweep

- **Dependabot-patch auto-merge class** — requires a real Dependabot patch
  PR authored by `dependabot[bot]`; the classifier's docs-only path is
  proven, and the dependency-bot path is covered by unit tests, but its
  live behavior was not exercised here.
- **The head-changed-after-classification TOCTOU withdrawal** — the guard
  exists and is unit-tested; reproducing the race live was out of scope.
- **Dependabot/secret-scanning alert APIs** — the same `403` token-scope
  gap noted in the 2026-08-17 security report applies to these test repos.

## Verdict

Every shipped surface works live end to end, including the two
highest-stakes features: tiered auto-merge (classified, gated on required
checks, merged with no human, with a working audited break-glass path) and
the scheduled stewardship loop (opens one deduplicated issue only on
WARN/FAIL, silent when healthy). The two bugs found are both in generated
output, both High because they hit a consumer on day one, and both
one-to-a-few-line fixes that a normal orchestrated run can carry.
