# 0011 — Marketing site on GitHub Pages, README art generated from it

Date: 2026-10-12

## Status

Proposed

## Context

Shipshape needs a public front page that explains it to people who have
never heard the word "CI", and the README should look like the same
product. GitHub sanitises README HTML: no stylesheets, no classes, no web
fonts. Images are the only way to carry typography and colour into it, and
`<picture>` with `prefers-color-scheme` is GitHub's supported way to serve
light and dark variants.

## Decision

1. The marketing site is plain static HTML and CSS in `site/`, with no build
   step and self-hosted fonts (OFL licences alongside). A repo-local
   workflow, `.github/workflows/pages.yml`, deploys it to GitHub Pages when
   `site/**` changes on `main`, with least-privilege permissions.
2. The README keeps its words, headings, command table and install block as
   Markdown, so they stay searchable, linkable and copyable. Its visual
   sections (hero, course, conversation, watch bill, install, footer) are
   SVGs in `site/assets/readme/`, each in a light and a dark variant.
3. Those SVGs are generated by `site/tools/build_readme_art.py`, which
   embeds subsets of the site's own fonts and mirrors the site's colour
   tokens. It is a dev-only tool that needs fontTools and brotli. The
   plugin download includes it, because the plugin source is the whole
   repository, but nothing in the kit ever runs it on a consumer machine.
   So [ADR 0002](0002-python-stdlib-scripts.md)'s stdlib-only rule, which
   governs the kit scripts in `scripts/`, does not apply to it. Its output
   is byte-for-byte reproducible for a given fontTools and brotli version.
4. `tests/test_site.py` fails CI if the README or the site points at an
   asset that does not exist.

## Consequences

- Copy or colour changes to the README art mean editing the generator and
  re-running it; the SVGs are build output and are not edited by hand.
- The site's colour tokens (`site/styles.css`) and the generator's `THEMES`
  are kept in step by hand.
- Pages needs a one-time repository setting (Pages source: GitHub Actions)
  before the first deploy succeeds.
